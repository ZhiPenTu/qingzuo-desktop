# 轻作 UI 审查

只读审查界面，目标是让界面像轻作工作台的一部分，而不是另一套产品。

## 规范来源

- `docs/design/qingzuo.md`
- `docs/design/plugin-ui-guidelines.md`
- 相关 React 组件、CSS 变量和现有页面

## 检查项

1. 浅色工作区保持纯白 `#ffffff`，窗口外壳与工作区层级清楚；深色模式不套用浅色表面。
2. 墨绿/薄荷绿只用于主操作、当前选择和焦点；不引入紫色、靛蓝或无关品牌色。
3. 标题、正文、控件和辅助文字的字号与字重符合规范；不用缩小字体制造紧凑。
4. 卡片、按钮、输入框的圆角、边框、间距和留白一致；不添加装饰性阴影、玻璃拟态或渐变。
5. 一个区域只有一个主操作；次要操作使用边框或幽灵按钮。
6. 键盘焦点、可访问名称、颜色对比和状态图标齐全。
7. 宽屏、窄屏、长文本和插件嵌入场景不溢出、不遮挡、不丢失主操作。
8. 插件页面只使用 `--qz-*` 局部语义变量，不依赖宿主主题或内部 CSS。

## 证据

- 需要截图、控制台或网络信息时，使用项目内 Playwright 和本地 Vite/Electron 页面，产物写入被忽略目录。
- 标注页面、视口、明暗主题和证据类型。
- 区分 Vite 页面、真实 Electron 页面和静态代码判断。
- 公开设计资料或上游文档用 `$mcp-evidence`（`magpie`），不要用它冒充页面证据。

## 输出

- 按严重程度排序的问题。
- 对应页面、组件、设计令牌和证据位置。
- 最小修复建议和需要重新验证的场景。

## 边界

- 不修改文件，不提交、不推送。
- 不把个人偏好当作规范问题；每条发现都要能指向设计规则或实际可用性影响。
