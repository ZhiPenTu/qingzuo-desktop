# 仓库架构定位

在规划复杂改动、定位跨进程问题或需要把调查结果交给实现代理时使用。默认只读。

## 输入

- 用户描述的问题、功能或改动范围。
- 当前分支的 `AGENTS.md`、`docs/architecture.md` 和相关模块文档。
- 相关源码、测试、工作流和当前 diff。

## 步骤

1. 用 `rg`、`rg --files` 和定向文件读取确认入口，不要先做全仓扫描。
2. 从真实入口追踪调用链：渲染进程、preload、主进程、IPC、Broker、Harness 内核、Rust 沙箱和插件 Worker。
3. 标出信任边界：哪些代码是受信任宿主，哪些是插件页面或 Worker，哪些数据可以跨边界。
4. 对齐 `docs/architecture.md` 与实现；文档和代码不一致时，以代码和可执行测试为准，并记录差异。
5. 找出最小测试面：平台契约、Electron 流程、沙箱、Harness 契约或纯前端测试。
6. 把事实、推断和未验证项分开列出，不要把推断写成结论。

## 输出

- 受影响模块和入口路径。
- 端到端数据流与信任边界。
- 相关测试、工作流和文档。
- 仍未确认的问题，以及建议由哪个代理继续调查或验证。

## 边界

- 不修改文件，不提交、不推送。
- 不提出无关重构，不把大范围重写当作默认方案。
- 需要公开上游文档证据时调用 `$mcp-evidence`（`magpie`）；浏览器证据用本地 Playwright。
