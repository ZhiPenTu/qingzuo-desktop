# 电商工具桌面底座：最终目标任务书

## 最终目标

将 LabelEdit 进化为电商行业插件服务的统一入口。用户通过一个桌面应用发现、安装、配置、使用和更新插件；开发者通过新增插件扩展产品，无需修改或重新发布底座。

底座直接复用 DeepSeek Harness 的运行内核，使用自己的界面，并持续吸收经过验证的上游更新。素材处理由各插件负责。

## 已确定的范围

- Electron + 内置 Node，React + TypeScript 自有界面，主窗口工具标签页。
- 官方 Harness 包依赖，固定 @deepseek-ai/dsh@0.2.2-alpha.2；自定义 commerce-desktop Profile 和产品 Bundle。上游升级必须经过回归测试，保留 MIT 和第三方声明。
- 首页、市场、插件管理、设置、更新、凭据和沙箱按受保护的系统插件组织。
- 网页与本地处理插件；SDK、模板、打包、本地导入、独立安装/停用/卸载/更新，以及失败恢复。
- LabelEdit 默认附带，保留离线 PDF 编辑和 OCR，后端按需启动，改为受控 RPC。
- AI 抠图使用 remove.bg API，用户自带密钥；单图处理、前后预览、透明 PNG 保存，失败不自动重发。
- 市场第一版为线上目录与安装，不建设账号、支付及开发者自助发布。不承诺任意 Harness 插件即装即用。
- 插件界面独立沙箱；本地程序使用 macOS Seatbelt、Windows AppContainer + Job Object。文件、网络和凭据由宿主代理，沙箱失败必须阻止执行。
- 底座与插件分别维护版本，更新只展示最新版本变更日志。

## 阶段和完成标准

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| 1 | 内核与桌面壳 | 不加载上游界面即可启动；服务注册、调用、卸载完成真实测试 |
| 2 | 插件隔离 | 两个平台真实进程越权测试通过；不存在不安全降级 |
| 3 | 平台与 LabelEdit | 默认离线插件完成 PDF/OCR/编辑/导出回归；工具中心不受后端失败影响 |
| 4 | 市场与扩展 | 市场安装抠图及导入自制插件，无需重编译底座 |
| 5 | 发布与上游升级 | GitHub 分发、安装、最新日志、手动更新和失败恢复通过；完成上游升级演练。发布者签名和标准自动安装更新为后续可选模式 |

## 验收和发布

- 新增工具可被自动发现并独立更新。
- LabelEdit 的打开、OCR、编辑、预览和导出通过回归。
- AI 抠图真实 API 调用及保存通过；缺少凭据、额度不足、取消和断网反馈明确。
- 使用真实进程验证目录外读取/写入、其他插件数据、直接联网、未授权程序启动均被阻止；使用测试哨兵文件，不访问真实秘密。
- 包损坏、签名错误、版本不兼容、依赖缺失、升级失败不会破坏工具中心。
- 停用、卸载、退出后无残留处理进程或注册项。
- 上游升级不破坏生命周期、权限边界与两个官方插件。
- macOS 14+ Apple Silicon、Windows 10+ x64；公开版本规划 v0.2.0。
- 按用户 2026-10-09 的补充决定，先通过 GitHub 发布未签名桌面安装包，不上架 App Store；Apple Developer ID、公证和 Windows 发布者签名不再是当前发布前置条件。macOS Apple Silicon 保留运行所需的 ad-hoc 签名，它不证明发布者身份。
- 按用户 2026-10-09 的更新要求，底座手动检查最新正式版本并展示该版日志；点击更新后在应用内显示下载进度，校验、安装并自动重启。未签名 macOS 使用 GitHub ZIP 的 SHA-256/大小、应用标识/版本和 ad-hoc 签名校验，替换失败时尝试恢复原应用；Windows 与正式签名构建沿用 electron-updater。插件市场目录保留旧条目的 Ed25519 签名兼容；收录来源的新版本从插件 Release 读取并校验身份、来源、大小与摘要。
- remove.bg 真实 API 验收按用户决定暂缓，不作为当前桌面分发流程的阻塞项；不能将尚未验证的 API 能力标记为完成。
- 旧用户手动安装新底座，不建设自动迁移桥。按用户 2026-10-09 的补充决定，移除旧版下载与 Tauri 更新清单。
- macOS sandbox-exec 已弃用，其真实系统可用性是发布门槛，不可用时拒绝启动本地插件。

最终完成标志：用户在同一入口使用 LabelEdit、安装 AI 抠图、添加自制工具；开发者独立发布插件，底座经过验证持续升级 Harness 内核。

实施状态及证据见 implementation-status.md；仅有代码不代表验收完成。


## 完整架构与插件契约

| 层级 | 职责 |
| --- | --- |
| Electron 桌面壳 | 窗口、隔离插件页面、权限代理、可信 IPC、宿主监督与恢复 |
| DeepSeek Harness 内核 | Profile/Bundle 组合、Cordis 服务与依赖、插件生命周期、配置和管理 |
| 受保护的系统插件 | 工具中心、市场、插件管理、设置、更新、凭据及沙箱 |
| 工具插件 | LabelEdit、AI 抠图及用户开发的电商工具 |

通过公开 Profile 启动接口运行 commerce-desktop 组合，由自己的 Bundle 加入产品功能。首版仅启用平台需要的内核服务，保留上游 Agent、MCP 后续接入路径。首页、市场、设置、更新均按插件组织，关键组件只接受受信任系统实现。上游升级通过依赖更新、适配检查和回归后随底座发布；不承诺任意 Harness 插件即装即用。架构参考：https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md。

沿用 DSH/Cordis 服务、依赖和生命周期规范，在 package.json 增加 commerce 描述，声明界面入口、兼容版本、平台资源、权限和服务贡献。首版插件包为包含已构建界面、程序及依赖的 ZIP 制品，用户无需 Node、Python 或包管理器。SDK 提供工具注册、设置贡献、服务调用、文件选择保存、凭据配置、受控网络、任务取消和资源清理。插件独立安装、启停、卸载和更新；停用释放页面注册、事件和处理进程。安装进入暂存区，校验结构、平台、版本兼容再激活；升级失败保留并恢复上一版本。官方制品须签名验证，本地包显示来源并遵守同样隔离规则。生产不执行安装脚本，包管理不向界面暴露任意命令入口。

## 系统级沙箱的硬性要求

生命周期隔离与系统安全隔离分别实现。第三方代码不可直接加载进具有宿主权限的内核进程。

- 页面使用独立沙箱渲染上下文，关闭 Node 集成，通过身份校验接口访问底座。
- 本地程序由原生启动器运行：Windows AppContainer + Job Object，macOS Seatbelt。
- 程序只能读取自身制品、必要运行资源及已授权输入，只能写自身数据与任务目录。
- 用户文件由宿主选择器授权并复制到任务目录；输出由宿主保存到用户指定位置。
- 直接联网默认禁止，在线服务经权限代理按插件校验域名和凭据引用。
- 禁止其他插件数据、系统凭据和未授权进程；限制可执行程序并在任务完成后清理后代进程。
- 沙箱不可用时明确报错并阻止本地程序，禁止普通进程降级。sandbox-exec 已弃用，其真实系统验证为发布门槛。

## 官方工具的完整要求

LabelEdit 复用编辑界面和 PDF/OCR 逻辑，将桌面处理通道改为宿主管理 RPC。Python 程序、字体和 OCR 资源归插件，打开工具后按需启动。PDF 打开、OCR、文字编辑、预览、导出全部回归，后端失败不影响工具中心。

AI 抠图支持单图选择、在线处理、前后预览、透明 PNG 保存。密钥存系统凭据库，由网络代理注入请求。显示上传目标、凭据错误、额度不足和网络失败；失败不自动重发以避免重复计费。真实 API 与取消、缺少密钥、额度及网络错误都必须有验收证据。

## 后续验收的完整边界

新增插件后自动显示工具入口，其安装更新不要求底座重新发布。两平台使用真实进程而非仅模拟测试证明不可读取未授权哨兵、修改目录外文件、访问其他插件数据、直接联网或启动未授权程序。损坏包、签名错误、版本不兼容、缺依赖和升级启动失败均不可破坏工具中心。停用、卸载、退出不得残留处理进程或注册项。上游内核升级后，自有界面、插件生命周期、权限边界和两个官方插件仍可用。

第一版不包含通用 AI 对话、付费市场、账号支付、自助发布或上游插件广泛兼容，另立后续任务。两平台实际安装/手动更新、插件签名及一次上游升级演练通过后，才能宣称当前 GitHub 公开版本完成。后续启用发布者签名时，另外验证 Apple 公证、Windows 代码签名及标准 Electron 自动更新。
